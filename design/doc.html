简介与快速上手

⏱ 预计阅读 5 分钟 适用于 net8.0 / net10.0 / net11.0 当前文档对应 v3.4.5.27

CodeWF.EventBus 是一个轻量的进程内事件总线，用「命令分发 + 查询回传」两个原语解决模块间通信问题。如果你用过 MediatR 或 Prism.Events，可以把理解成本降到最低——它更小、更快、无第三方依赖。

💡 何时选 EventBus

单体应用内的模块解耦选 EventBus；需要跨进程通信时升级到 CodeWF.EventBus.Socket（TCP 事件总线），API 风格完全一致。

安装

按使用的 IOC 容器选择集成包；不确定就用核心包 + 手动注册：

bash
dotnet add package CodeWF.EventBus# ASP.NET Core 项目：dotnet add package CodeWF.AspNetCore.EventBus

定义命令与查询

命令表示「要执行的动作」，查询表示「要取回的数据」，都是普通记录类型：

C#
using CodeWF.EventBus; // 命令：发布后由处理器并行消费public record SendEmailCommand(string To, string Title) : ICommand; // 查询：发布后取回一个结果public record GetUserQuery(int Id) : IQuery<UserDto>;

注册与发布

C#
// 1. 注册（ASP.NET Core 示例）builder.Services.AddCodeWFEventBus(typeof(SendEmailCommand).Assembly); // 2. 注入 IEventBus 并发布public class OrderService(IEventBus eventBus){ public async Task PlaceOrderAsync() { await eventBus.PublishAsync(new SendEmailCommand("dev@codewf.com", "下单成功")); var user = await eventBus.QueryAsync(new GetUserQuery(42)); }}
✅ 与 UI 框架集成

Avalonia / WPF / WinForms 中同样可用，配合 DryIoc 集成包可在 Prism 应用里无缝使用，详见容器集成指南。

编写处理器

处理器就是实现了对应接口的普通类，由容器自动发现并注册：

C#
public class SendEmailHandler : ICommandHandler<SendEmailCommand>{ public Task HandleAsync(SendEmailCommand command, CancellationToken ct) => mailSender.SendAsync(command.To, command.Title);}

与 MediatR 的差异

能力CodeWF.EventBusMediatR
命令分发✅ ICommand✅ IRequest
查询回传✅ IQuery<T>✅ IRequest<T>
核心包依赖零第三方依赖依赖 Microsoft.DI 抽象
容器无关✅ 任意容器需容器适配
NativeAOT✅ 验证工程随仓库维护社区方案
